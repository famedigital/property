3. Anti-skimming & rent flow

Stop “manager eating the money”: residents never pay into the manager’s personal account by default.

Broken today: cash/transfer to manager → under-reporting, fake vacancies, Excel receipts.
Product rule: pay-to-owner rail · immutable ledger · owner sees expected vs collected live.
flowchart LR Resident2["Resident"] -->|invoice pay| Rail["Payment rail"] Rail -->|rent| OwnerBank["Owner bank"] Rail -->|optional fee| PMFee["PM fee"] Rail -->|thin fee| PlatFee["Platform"] OwnerDash["Owner dashboard"] -.->|expected vs paid| OwnerBank

Hard controls

  • No silent “mark paid” without webhook or owner OTP for cash
  • Payments cannot be deleted — void/refund with audit only
  • Every active lease auto-invoices; vacancies visible to owner
  • Manager fee capped %/flat on every receipt
  • Arrears alerts go to owner directly

11. MVP roadmap

  1. Foundation — monorepo, Postgres schema + RLS RBAC, auth, seed
  2. Property CRUD — orgs, buildings, units, memberships
  3. Rent-to-owner — leases, invoices, Connect-style payout, owner ledger
  4. Owner tank + LoRaWAN — 1 gateway, ChirpStack, live level
  5. Source alerts — upstream node + push/SMS P0/P1
  6. AI enrich — alert explain + owner brief behind Gateway key
  7. CCTV link — source clip on critical alerts (permits)
  8. Edge sync — gateway local buffer when 4G drops
  9. Phase 2 — corridor densify, autopay, Thromde coexist

12. Open decisions

  • Mobile: Expo default (plan) vs Flutter if rejecting React Native
  • Sensor hardware: ultrasonic / pressure / Modbus gateway
  • Data region / residency
  • Residents in MVP vs managers/owners only
  • Payment rails for Bhutan / region (Connect-style or local)
  • Which Thimphu source corridor for pilot + Thromde access for CCTV
